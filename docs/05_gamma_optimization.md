# 5. Inferring gamma drive by optimization

Fusimotor (**gamma**) drive is hard to measure directly in behaving animals. The
`gammaDriveOptimization` project infers it *indirectly*: it asks **what gamma
drive would make the model reproduce a recorded Ia signal?** — and finds it by
optimization.

## The idea

```
   guess gamma parameters
          │
          ▼
   run the spindle model  ──►  predicted Ia
          │                          │
          │                     compare (cost)
          ▼                          │
   adjust parameters  ◄──────────────┘   (repeat until the fit is good)
```

An optimizer (`fmincon`, in the manuscript wrapped in a pattern-search + `fmincon`
**hybrid grid** to escape local minima) minimizes the mismatch between the
model's Ia and the target. In the real project the target is experimental Ia data
(Taylor et al.).

## What the tutorial actually runs

The **Gamma optimization** tab calls the manuscript's *own* functions —
`runSpindleSimForOpt_Bspline_5cp` and `getIntrafusal_pCa_Bspline_5cp` from
`gammaDriveOptimization` — so the pipeline is the published one, not a
re-implementation. The only change is that the **target is generated by the model
itself** from a known gamma drive, so the "right answer" is known and can be drawn
alongside the recovered result. `tutorialOptDemo.m` sets this up.

The setup matches the manuscript's final workflow
(`runOptimizedSimulation_HybridOpt_Bspline_5cp_grid.m`):

- **Extrafusal MTU:** a sinusoidal (gait-cycle) length with α drive; the fascicle
  length drives the intrafusal fibers. It does not depend on gamma drive, so it is
  computed **once** and reused on every objective evaluation.
- **Gamma static (chain):** a periodic **B-spline with 5 control points** (in pCa)
  plus a phase shift — a flexible fusimotor waveform over the gait cycle.
- **Gamma dynamic (bag):** a phasic burst; here we fit its **magnitude**, with the
  ON/OFF **timing held fixed** (the manuscript optimizes timing in an outer grid).

### Fitted parameters

`x = [bag burst pCa, cp1, cp2, cp3, cp4, cp5, phase]` — the bag burst magnitude,
the five gamma-static control points, and the waveform phase (7 parameters). The
tab plots the **recovered gamma** — both the gamma-static waveform (with its
control points) and the gamma-dynamic burst — against the known truth, so you can
see how faithfully the drive is recovered.

### Objective

The total Ia is dominated by the bag fiber's large dynamic response, so a plain
RMSE on `r` would give the chain (gamma-static) parameters little leverage. The
objective therefore compares the **static (`r_s`) and dynamic (`r_d`) components
separately, each normalized** by its own scale, so both the gamma-static waveform
and the bag magnitude are identifiable. With a long-enough horizon (a couple of
gait cycles), all seven parameters recover to ~95–100% and the cost falls close to
zero.

### Notes on identifiability and speed

- **Timing** (when gamma-dynamic turns on/off) is fixed here; it sits on a sharp
  transient and is hard to identify from a single trace — a real limitation the
  manuscript handles with the outer grid / multi-start.
- **Phase** is the most weakly identified of the fitted parameters; a longer
  simulation horizon (more gait cycles) constrains it better.
- Each objective evaluation runs the full model, so a fit takes ~1–2 minutes.
  Ticking **Use parallel** spreads the finite-difference gradient across workers
  (needs the Parallel Computing Toolbox).
